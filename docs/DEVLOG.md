# 開發日誌

每天收工前寫 3–5 行：做了什麼決策、為什麼、卡在哪裡。這是作品集的原始素材。

## Day 1–3（設計階段，已完成）

- 定位收斂為「紙本題本的閱讀錯題本」，聽力交給 VoiceTube，刻意不做。
- 首頁命名為「複習」，第一次使用的困惑交給空狀態文案解釋，不另做教學頁。
- 錯因多選用平鋪標籤而非下拉選單：錄入速度優先，最多顯示 8 個，其餘收合。
- 答對時「猜的」與「有把握」並排，避免記住答案的題目被誤判為已學會。
- 視覺選「冷白書頁＋鋼筆藍＋書籤分色」：顏色是資訊，不是裝飾。

## Day 4（專案骨架）

- 日期全部走 `src/lib/date.ts` 的本地日曆計算；測試固定在 `Asia/Taipei` 執行，並加一個「台灣 07:30 = UTC 前一天 23:30」的案例，證明 `toISOString()` 會算錯日。
- Tailwind 用 `--color-*: initial` 清掉預設色票，元件只能用 DESIGN.md 的 tokens；文字樣式也做成 `text-title`、`text-body` 等 tokens（Body/Base 命名為 `text-body`，避免覆蓋 Tailwind 的 `text-base`）。
- 預設錯因與設定用 Dexie 的 `populate` 事件建立：只在資料庫第一次建立時執行，重開不會重複。
- 導覽列只出現在複習、錯題庫兩個分頁；設定依 Figma 5-1 為返回式頁首、沒有導覽列。流程頁的 ✕／‹ 優先返回上一頁，直接開網址時回到預設頁。
- 卡關：Windows 上 headless Edge 的視窗有最小寬度，`--window-size=390` 不準，改用 390px 寬的 iframe 檢查畫面。
- 部署：GitHub repo 匯入 Vercel（https://dog-ear-two.vercel.app），之後 push 到 main 就自動部署。iPhone Safari 加入主畫面後以全螢幕開啟、三個分頁可切換、飛航模式下仍可開啟，Day 4 驗收通過。

## Day 5（錄入流程）

- 規格沒寫的四件事先跟自己確認再做：✕ 離開時若已存過題目，視同「略過」寫入 PracticeSession（避免題目的 `sessionId` 指向不存在的紀錄）；縮圖可刪除；缺少欄位提示沿用「還沒選正確答案」的句型；新增錯因後自動展開「更多錯因」，因為使用 0 次的新錯因會排到第 9 個以後。
- 「中途離開確認」不是看「欄位有沒有值」，而是跟表單重設時的狀態比：自動帶入的題本來源、沿用的照片與 Part 都不算「已填」，否則「再拍一題」之後每次按 ✕ 都會被問。
- 錯因使用次數只讀 `*errorTagIds` 多值索引的 key，不把題目（含照片 Blob）整筆載入記憶體。
- 照片元件改成在 effect 裡直接設定 `<img>` 的 src 並在卸載時 revoke，避開「effect 裡 setState」的 lint 警告，也不會在 StrictMode 重跑 effect 時拿到已 revoke 的網址。
- 輸入框字級一律 16px：iOS Safari 對小於 16px 的輸入框聚焦時會自動放大畫面。
- 驗證：用 headless Edge + CDP 的 `setDeviceMetricsOverride` 模擬 390px（取代 Day 4 的 iframe 作法），腳本實際上傳 3024×4032 照片、走完三題錄入與練習量面板，42 項檢查全過；照片壓成 1200×1600 JPEG、約 24KB。真實題本與 30 秒的驗收要在手機上做。
- 部署後手機一開始還是舊版：Service Worker 只在冷啟動時檢查更新，iPhone 從背景切回 App 不算冷啟動；把 App 從多工畫面滑掉再開才換到新版。之後每次部署都會遇到，待決定是否改成「回到前景時檢查更新」。
- 手機驗收（iPhone，真實題本）：單題錄入約 30 秒，剛好達標、沒有餘裕；「沿用這組照片」連續新增多題正常；關掉重開後資料仍在（錄入頁的錯因順序依使用次數改變）。Day 5 驗收通過。
- 修正更新問題：PWA 改為 `prompt` 模式，由 `src/lib/pwa.ts` 控制。App 回到前景時主動檢查新版；新版下載後若在錄入或複習中就先等待，離開該畫面時才套用並重新整理，避免清掉填到一半的表單。用 build 版本實測三種情境（錄入中不重整、離開後套用、首頁回前景直接更新）皆通過。

## Day 6（複習排程與今日複習）

- 開工前先確認 6 個規格空白：每日上限扣掉今天已複習的題數（中途離開再進來不會超量）、完成畫面數據算今天全部、「明天有 N 題」受每日上限限制、N 為 0 時改顯示「下次複習在 11/16」、答錯卡片可追加錯因與編輯筆記、本週從星期一開始。
- `scheduler.ts` 只放純函式（排程、出題排序、每日上限），統計放 `stats.ts`；資料庫存取集中在 `db/review.ts`。作答時題目更新與 ReviewLog 寫在同一個交易裡，不會只寫一半。
- 首頁數據都用索引查詢（`nextReviewDate`、`createdAt`、`reviewDate`），不把題目連同照片整筆載入；已掌握的題目 `nextReviewDate` 為 null，本來就不在索引裡。
- 卡關：揭曉卡片的標題看不到。原因是字級 token `--text-card` 產生的 `text-card` 和顏色 token `--color-card`（白）撞名，標題變成白字。自動測試只檢查文字存在所以沒抓到，是看截圖才發現。字級改名為 `--text-heading-card`，e2e 腳本加上「計算後的顏色與字級」檢查。
- 卡關：Day 5 停掉的 dev server 其實還在背景跑（只停了 npx，沒停到子程序 vite），新開的 server 搶不到 port。之後停 server 時改用 port 找到實際的 vite 程序再關。
- 驗證：390px 實測完整核心循環 32 項（錄入 → 開發用按鈕設為今天 → 答錯／不會／答對 → 完成 → 中途離開再進來），單元測試 88 個。
- 卡關：部署後 iPhone 首頁整頁顯示「Unexpected Application Error」，錯誤訊息是 `UnknownError: Unable to open cursor`。首頁數據的 `uniqueKeys()`（連續天數）與 `first()`（下次複習日）都會開 IndexedDB cursor，iOS Safari 在資料表為空時開 cursor 會失敗（剛好還沒有任何複習紀錄）。電腦上的 Chromium 與 WebKit 都重現不出來，是拿到手機上的錯誤訊息才定位。改成只用 getAll／count 類查詢（讀全部 ReviewLog 取日期、`limit(1).toArray()`），並加測試確保首頁數據不開任何 cursor。修正後手機首頁正常，新增題目正常、數字正確。
- 待驗證：錄入頁的錯因排序仍用多值索引的 `keys()`（會開 cursor），目前手機上正常；若之後出現同樣錯誤，改用同樣方式處理。
- 手機驗收（iPhone，11/14）：隔天實際走完今日複習流程，沒有問題。Day 6 驗收通過。

## Day 7（錯題庫）

- 開工前先確認 15 個規格空白，全部照建議：篩選點了立即生效、面板用「完成」關閉；錯因多選為「任一符合」；篩選按鈕顯示所選內容（錯因超過兩個顯示「錯因 3」）；封存錯因只在還有題目使用時出現在篩選；⇅ 切換兩種排序；逾期的下次複習日顯示「今天」；篩選與排序在 App 執行期間保留、重開回預設；「清除篩選」連狀態一起改成「全部」；錯題庫沒有題目時沿用首頁空狀態；作答紀錄舊到新、沒有紀錄顯示「還沒有複習過」；已到期的題目「加入今日複習」改成不能按的「已在今日複習」；重設與刪除的確認文案；編輯頁為全螢幕「編輯錯題」；照片全螢幕檢視（雙指縮放、點兩下放大、左右滑動），詳情與今日複習共用。
- 錄入表單抽成 `QuestionFields`＋`useQuestionForm`，錄入與編輯共用同一份表單；「有沒有未存檔的內容」改成逐欄與載入時的狀態比較，編輯時也能正確判斷。編輯時如果題目標了已封存的錯因，也會列在錯因裡，才能看到並取消。
- 延續 Day 6 的 iOS cursor 問題：用索引條件 `delete()` 刪作答紀錄時 Dexie 會開 cursor，改成先 `primaryKeys()`（getAllKeys）再 `bulkDelete`。
- 編輯錯題頁有填到一半的表單，加進「不能自動更新」的畫面。
- 照片全螢幕：沒放大時 `touch-action: pan-x` 交給瀏覽器左右滑動換照片，雙指縮放由程式處理；放大後 `touch-action: none`，拖曳也自己處理，並限制不能拖出照片範圍。
- 卡關：e2e 腳本從外部直接寫 IndexedDB 時，Dexie 的 `liveQuery` 不會知道（只監聽自己連線的寫入），畫面不會更新；腳本改成寫完後重新整理。App 本身的寫入都走 Dexie，沒有這個問題。
- 驗證：390px 實測 51 項（列表、篩選、排序、詳情、重設、加入今日複習、全螢幕照片、編輯、刪除、篩選保留），另以觸控事件模擬雙指縮放與拖曳 5 項；Day 5（42 項）、Day 6（32 項）重跑全過。單元測試 108 個。三項驗收（篩出「單字」、編輯後資料正確、刪除連同作答紀錄）都在自動測試中通過，手機實測待做。
